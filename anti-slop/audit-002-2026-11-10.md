# Anti-Slop Audit 002: MagicPath Homepage Preview
Date: 2026-11-10
Target: MagicPath component `KhepiLabs Home Page Preview` (`breezily-autumn-2373`), revision `470501834054844416`
Design direction: repository `DESIGN.md`
Mode: AFTER

This audit covers the MagicPath preview component only. It does not change the GitHub production source or the deployed website. Findings are based on the submitted TSX/CSS and the rendered MagicPath preview. A build completed for the submitted revision; that confirms compilation only, not interaction, accessibility, responsive, or content correctness.

## Findings

### 1. HIGH — Demo content is presented as real catalogue data
**Rules:** R-17, R-18, R-38; C-5.
The preview hard-codes six named apps/games, publisher names, versions, file sizes, ratings, download counts, update timestamps, descriptions, and changelog entries. These values read like real listing facts, but the component has no live catalogue connection and no visible demo-data disclosure. The hero also presents KhepiTube with a 4.8 rating and 12.4K downloads. This creates fabricated evidence and trust signals.
**Fix:** Replace invented records and metrics with clearly labelled sample content, or use an honest empty/preview state. Keep only values supplied by actual listing data. Do not imply a live catalogue.

### 2. HIGH — Several navigation destinations are not implemented
**Rules:** R-24, R-26; C-2.
The header includes Updates and Admin Login links. Updates changes the hash to `#/updates`, while Admin Login changes it to `#/admin`; the component does not implement corresponding page views or an authenticated admin flow. The visual controls imply destinations that the preview does not provide.
**Fix:** Connect each control to a real page/flow available in the preview, or remove/clearly disable it with an honest “Not available in preview” state. Keep catalogue filters as working controls.

### 3. MEDIUM — Visual direction conflicts with KhepiLabs DESIGN.md
**Rules:** R-01, R-29, R-37; C-1.
The rendered preview defaults to a light lavender/purple treatment, gradient hero/product surfaces, ambient background glows, and purple primary actions. The written direction calls for a dark, quiet canvas, mint signal colour, solid surfaces, restrained borders, and light mode as a neutral alternative. The current preview therefore reads as a separate generic template rather than the established KhepiLabs identity.
**Fix:** Apply the documented dark palette as the default; retain light mode only as a neutral alternate. Reserve mint for brand, focus, key links, and selected states. Remove ambient glow/gradient treatments unless a specific content purpose is documented.

### 4. MEDIUM — Template-like hero and repeated pill treatment dilute catalogue hierarchy
**Rules:** R-05, R-09, R-10, R-11; C-1, C-3.
The page combines a generic “Discover & Download Quality Apps and Games” hero, eyebrow label, two broad CTAs, a large featured carousel, rounded category chips, pill-shaped search, and repeated rounded controls. The rounded/glossy treatment appears across navigation, filters, buttons, and cards without a clear hierarchy. The page gives more space to promotional framing than to the catalogue fields users need to compare.
**Fix:** Make catalogue discovery the first visual priority. Reduce the hero to a concise statement and one meaningful action, remove redundant eyebrow copy, and use restrained control shapes with clear active states. Give app name, icon, version, category, and source details the strongest hierarchy.

### 5. LOW — Decorative glyphs and icon language are inconsistent with the brand
**Rules:** R-04, R-31.
Navigation and app tiles use assorted Unicode symbols (including house, clover-like, star, pencil, and circular glyphs) as icon substitutes. Some glyphs are decorative rather than semantically tied to a labelled action; the preview also uses a star-like mark for Pixel Quest.
**Fix:** Use the existing KhepiLabs geometric mark only for brand identity. Use a small, consistent set of relevant action icons where they improve recognition, otherwise use text labels. Do not use star/sparkle-like marks as generic decoration.

### 6. MEDIUM — Preview states and responsive behaviour are not yet verified
**Rules:** R-03, R-27, R-34, R-35; C-4.
The component has filtering, search, theme switching, a detail overlay, and mobile menu state, but no evidence yet verifies the narrow-screen layout, touch equivalents, no-overflow behaviour, reduced-motion handling, or distinct loading/empty/error states. The current static demo list can also make a zero-result filter look like an incidental blank area unless a deliberate empty state is present.
**Fix:** Add clear no-results and empty-preview states, then verify keyboard and touch operation, visible focus, reduced motion, and layout at phone, tablet, and desktop widths before calling the preview complete.
